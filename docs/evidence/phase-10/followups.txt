Batch B: recovery and monitoring, rehearsed in CI (items 3 and part of 5)
-------------------------------------------------------------------------

Why in CI: the local PostgreSQL server also holds other projects'
databases (one of them a copy of a production system), so nothing
cluster-wide (WAL archiving, restarts) is done on it; and creating the
local drill database needs the server's superuser, which this session
does not hold. A disposable GitHub runner is a separate machine with its
own servers and nothing to harm.

  PostgreSQL 18 server (port 5433, RESTORE_DB_HOST/PORT, new). Result:
    Restore drill passed: restore 0.3 s, total 0.3 s, backup age 0 h.
