## Batch 9.1 (2026-11-14): domain, data and actions

Implemented
- app/Modules/Requests: Domain (RequestStatus, Decision), Models
  (ApprovalRequest), Application (CreateRequest, UpdateDraft,
  SubmitRequest, DecideRequest; NotifyApprovers, NotifyRequester;
  RequestNotification), Database (migration, factory),
  RequestsServiceProvider (migrations, morph alias, outbox handlers).
- Access: requests.view_all, requests.decide; role approver; the
  administrator gets requests.view_all; permission matrix updated.
- Timeline labels and Arabic for every new audit action and the role.

Tests
- Unit: the state machine allows exactly draft->submitted,
  submitted->approved, submitted->rejected.
- Feature (SQLite and PostgreSQL): creation (UUIDv7, audit), drafts
  (requester only, optimistic lock refuses a stale form, no-op records
  nothing, non-draft refused), submission (requester only, idempotent,
  one outbox message), approver notifications (requester excluded, once
  despite a duplicate delivery), decisions (permission, own request,
  reason to reject, draft refused, idempotent repeat, second approver
  told it is decided, role removed just before -> refused), requester
  notified of the rejection with its reason, audit chain intact.
- Constraints (PostgreSQL): nine rows written past the actions, each
  refused by its named CHECK constraint; a requester with requests cannot
  be deleted (RESTRICT).
- Concurrency (PostgreSQL, real processes): two approvers, one approving
  and one rejecting at the same moment, five rounds: exactly one decision,
  one audit record and one outbox message each round, the other told
  "This request has already been decided."; four simultaneous submissions:
  one submission, one audit record, one message.
- PostgresConventionsTest covers the new table (timestamptz, indexed
  foreign keys).

Defects found and fixed during the batch
- The rejection-reason CHECK let a NULL reason through (a CHECK passes on
  NULL; length(btrim(NULL)) > 0 is NULL). Found by the constraint test;
  NULL is now named, and two more rules were tightened the same way
  (decider and decision time together; decided after submitted).
- Concurrency tests replaced the outbox handler list with their own, which
  hid the module's handlers; they now add to it.
- A six-way submission race once exceeded the owner role's CONNECTION
  LIMIT 10 in the full suite ("too many connections for role"): the limit
  working. The race uses four processes; the assertion now prints any
  worker's error.

Gates
- SQLite: 294 passed, 31 skipped; PHPStan 0; deptrac 0; architecture and
  module boundary tests pass with the first real module.
- PostgreSQL: 323 passed, 2 skipped, twice in a row.
- Chromium: 205/205 (role lists now include the approver).
- Bundle: base 182.0 kB (budget 185).

Batch 9.2: the interface and integration (2026-11-13)
=====================================================

What was added
- Http: RequestPolicy, form requests (Precognition), RequestsTable
  (server-side list with status and scope filters), RequestPresenter,
  RequestController and AttachmentController (no base controller: the
  module's Http layer may not depend on App\Http, deptrac), routes with
  the UUID only and constrained to the UUID format.
- Contracts\RequestsOverview for the dashboard widget; navigation and
  notification links through the module's route helpers.
- Pages in resources/js/modules/requests/pages (list, form, request with
  files, history and the decision panel); the page resolver, the root
  view's preload, config/inertia.php and the bundle budget know the
  modules/<name>/pages/<page> rule.
- Browser test data: an approver with an authenticator app and one
  request waiting for a decision at a fixed UUID.

Tests
- Feature (RequestPagesTest, SQLite and PostgreSQL): who sees which
  request (403 for others), 404 for a malformed or unknown UUID, no
  internal id in the page, each field's check, Precognition checks one
  field without saving, a stale form is refused, a repeated submission
  click, an approver decides and the next is told it is already decided,
  a person without the permission gets 403, files only on a draft and
  only through their own request, the dashboard widget through the
  contract.
- Browser (requests.spec.ts, Arabic and English, three engines): draft
  checked while typing, saved, a file added, submitted, nothing editable
  afterwards; an approver signs in with password and authenticator code,
  a rejection without a reason is not sent, rejection with a reason;
  outbox relayed once; the requester follows the notification to the
  request and reads the reason; axe on the list, the form with an error,
  the submitted request, the decision panel and the rejection dialog.
- pages.spec.ts covers /requests, /requests/new and the waiting request.

Defects found and fixed during the batch
- Pressing a form's button moved focus off the last field, which started
  a live check, and the button was disabled while checking, so the press
  was lost and nothing was saved (found by the browser test in the full
  run: only the check requests reached the server). The same was latent
  in the profile and security forms. Buttons are now disabled only while
  sending; the server checks every field on saving.
- Placeholders were replaced in order, so ":to" broke ":total" ("1tal" in
  the pagination text). Placeholder names are now replaced whole; the
  browser test reads the pagination text.
- The history panel mixed in what a person with the same id had done;
  requests use includeActions: false.
- A malformed UUID reached PostgreSQL as a query error; routes now
  constrain the format (404).
- Factory requesters lacked a second factor, so the pages redirected to
  setup; the factory gives them one.
- In Playwright's Firefox, axe on the request right after it changed in
  place crashed the test page every time (not the app; Chromium and
  WebKit passed); the submitted request is checked on a fresh load. The
  approver test may wait up to 30 s for a fresh authenticator code and
  has its own 90 s limit.

Gates
- SQLite: 307 passed, 31 skipped; Pint, PHPStan 0, deptrac 0, vp check,
  tsc.
- PostgreSQL: 336 passed, 2 skipped.
- Full browser run before the fixes above: Chromium 241/245, Firefox
  239/245, WebKit 239/245; every failure was the dashboard widget count
  (now five widgets) or the defects above. After the fixes, on each of
  Chromium, Firefox and WebKit: requests.spec 8/8 (run twice), insights,
  forms and data specs 28/28. The full matrix runs again in CI.
- Bundle: base 184.3 kB (budget 185; 182.0 before the batch, the module's
  route helpers in the navigation and notifications); request pages
  +3.2, +29.5 and +17.3 kB (limit +35).
